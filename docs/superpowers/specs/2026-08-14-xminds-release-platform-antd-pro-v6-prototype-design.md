# Xminds Release Platform P0 控制台 Ant Design Pro v6 原型优化设计规格

| 项目 | 内容 |
|---|---|
| 文档版本 | v1.1 |
| 编制日期 | 2026-08-14 |
| 文档状态 | 已确认 |
| 设计基线 | Ant Design Pro v6.6.0、Ant Design 6、ProComponents v3 |
| 目标载体 | Open Design 网页管理控制台交互原型 |
| 执行方式 | Local Codex |
| 实施边界 | 仅优化原型视觉与交互表达，不进入业务代码实现 |

## 1. 背景

现有 Xminds Release Platform P0 原型已覆盖产品、制品、Release、SCM 连接、分发端点、日志中心和身份治理等模块，并具备发布审批、详情抽屉、日志关联检索、Git 同步重试和证据导出等交互。原型现已统一为浅色企业控制台，需固化组件尺度、层级、反馈和数据密度，避免后续实现回退到早期深色侧栏方案。

本次优化以 Ant Design Pro v6.6.0 为设计基线，保留现有信息架构、业务术语和全部有效交互，通过 ProLayout、PageContainer、ProTable、ProCard、ProForm 等模式固化可落地的企业级 Ant Design Pro 控制台表达。

本轮以“创建 Release—提交审批—发布—查看结果”为核心验收流程；产品、制品、SCM、分发端点和日志中心作为该流程的关联页面同步完成视觉统一与交互回归，不扩展新的独立业务流程。

## 2. 建设目标

1. 建立统一的 Ant Design 6 Design Token、间距、字体、圆角、阴影和状态色体系。
2. 使用 Ant Design Pro v6 的页面框架和数据密集型产品模式统一各业务模块。
3. 保留 Xminds 品牌辨识度，不制作成无差异的通用后台模板。
4. 提升发布流程、审批状态、异常定位和日志检索的清晰度。
5. 保留当前原型的全部核心交互，并准确表达已确认的身份治理和请求时授权快照模型。
6. 为后续 React 19、Ant Design 6、ProComponents v3 技术实现提供明确映射依据，但本阶段不编写业务代码。

## 3. 设计原则

### 3.1 企业级与克制

- 以信息效率和操作确定性为第一目标，避免大面积渐变、装饰性插画和过度动画。
- 主要工作区、左侧导航和详情抽屉使用白色内容表面，品牌识别通过 Logo、主色和选中态表达。
- 页面只保留一个明确的主操作，次要操作使用默认按钮、文字按钮或下拉菜单承载。

### 3.2 统一与可预测

- 同类页面使用一致的标题区、筛选区、表格区、详情抽屉和反馈位置。
- 同一业务状态在列表、详情、时间线和统计卡中使用相同的颜色、文字和图标语义。
- 危险、不可逆或高风险操作必须经过二次确认，并明确展示影响范围。

### 3.3 数据优先

- 减少无意义卡片嵌套，使用页面容器、分区标题和轻量边界建立层级。
- 表格优先展示决策所需字段，低频字段进入列设置或详情抽屉。
- 长摘要、Commit SHA、Request ID 和制品哈希使用等宽字体、截断和复制操作。

## 4. 视觉系统

### 4.1 色彩

| Token | 原型取值 | 用途 |
|---|---:|---|
| `colorPrimary` | `#1677FF` | 主操作、选中态、关键链接 |
| `colorBgLayout` | `#F5F7FA` | 页面工作区背景 |
| `colorBgContainer` | `#FFFFFF` | 表格、表单、卡片和抽屉表面 |
| `colorText` | `#1F1F1F` | 主要文字 |
| `colorTextSecondary` | `#666F7A` | 辅助信息 |
| `colorBorderSecondary` | `#F0F0F0` | 轻量分隔 |
| `colorSuccess` | `#52C41A` | 已发布、成功、健康 |
| `colorWarning` | `#FAAD14` | 待审批、高耗时、需关注 |
| `colorError` | `#FF4D4F` | 失败、拒绝、高风险 |
| `colorInfo` | `#1677FF` | 处理中、同步中、信息提示 |

颜色不作为唯一信息载体。所有状态必须同时具备文字标签，关键状态增加图标或 Badge 状态点。

### 4.2 字体与数字

- 中文及普通界面文字使用系统无衬线字体栈。
- 页面标题为 20px/28px、600；区块标题为 16px/24px、600；正文为 14px/22px。
- 指标数字、版本号、耗时和状态计数使用等宽数字特性，避免刷新时跳动。
- SHA、Request ID、Commit SHA 等技术标识使用等宽字体，默认单行截断，并提供复制反馈。

### 4.3 间距、圆角与阴影

- 使用 4px 基础单位和 8px 主节奏，常用间距为 8、12、16、24、32px。
- 表单控件默认高度 32px，关键主操作可使用 40px；表格常规行高约 48px。
- 控件和普通卡片使用 6px 圆角，抽屉、弹窗和大型容器使用 8px 圆角。
- 仅浮层、固定顶栏和悬浮操作使用低强度阴影，普通内容区域主要依赖边框和背景层级。

## 5. 总体框架

### 5.1 ProLayout 结构

- 左侧导航展开宽度 224px，折叠宽度 64px；侧栏、Logo 区和折叠控制区均为白色，并保留 Xminds 产品标识。
- 顶栏高度 56px，承载全局搜索、环境标识、通知、帮助和用户菜单。
- 内容区使用 `PageContainer` 模式，统一显示面包屑、页面标题、说明、状态和右侧操作。
- 桌面基准画布为 1440px，同时保证 1280px 宽度下不出现关键操作遮挡。
- 左侧导航和顶栏固定，内容区独立滚动；表格工具栏与表头在长列表中保持可见。

### 5.2 导航分组

| 分组 | 菜单 |
|---|---|
| 工作台 | 概览 |
| 发布管理 | 产品、制品、Release |
| 集成与分发 | SCM 连接、分发端点 |
| 可观测与治理 | 日志中心 |
| 系统管理 | 用户中心、角色与权限、身份源配置 |

当前激活项使用主色背景和清晰文字对比；导航图标统一使用 Ant Design Icons 线性风格，不混用 Emoji 或不同线宽的图标。

## 6. 页面与组件设计

### 6.1 概览

- 顶部使用 PageContainer 标题区，展示当前产品范围、环境和“创建 Release”主操作。
- 第一行采用 StatisticCard 展示待审批、发布中、失败任务、端点健康度四项关键指标。
- 第二行展示最近 Release 与系统风险提醒，避免超过两个并列主模块。
- 指标卡可点击进入对应筛选结果，失败和风险项提供直接处理入口。
- 删除装饰性图表；没有真实趋势语义的数据不绘制趋势线。

### 6.2 产品、制品和 Release 列表

- 统一使用 ProTable 结构：标题、辅助说明、搜索筛选、主操作、密度、列设置、刷新、表格和分页。
- 默认展示 5 至 8 个关键字段，低频字段进入详情抽屉或列设置。
- 批量操作仅在选中记录后出现，并显示已选数量及清空选择入口。
- 状态使用 Tag 或 Badge；失败原因在列表中给出简短摘要，完整内容进入详情。
- Release 表格突出版本、产品、通道、状态、提交人、更新时间和操作。
- 操作列最多直接展示两个高频动作，其余操作进入 `更多` 菜单。

### 6.3 Release 创建与审批流程

- 使用 StepsForm 风格表达“基本信息—选择制品—发布配置—确认提交”四步流程。
- 当前步骤突出显示，已完成步骤可回退编辑，未完成步骤不可直接跳转。
- 每一步只呈现当前决策所需字段，右侧或底部提供摘要区，持续展示产品、版本、通道和已选制品。
- 审批详情使用 Descriptions、Alert 和 Timeline 组合展示提交信息、校验结果和状态流转。
- 发布、驳回、撤销等高风险动作使用 Modal 确认，必须明确影响对象和后续结果。

### 6.4 SCM 连接与分发端点

- 使用 ProCard 分区展示基本配置、认证信息、网络策略和能力探测结果。
- 凭据字段默认脱敏，编辑与查看权限分离；任何示例数据不得展示完整密钥。
- 连接测试使用分阶段反馈：DNS、TLS、认证、API 能力和 Webhook 可达性。
- 分发端点使用健康 Badge、最近同步时间、目录摘要和失败原因形成可扫描列表。
- 同步重试在详情抽屉中以 Timeline 展示，不在主表格堆叠完整技术日志。

### 6.5 日志中心

- 保留操作日志、登录日志、应用请求日志和 Git 同步日志四个一级页签。
- 页签下方使用统一查询栏，高频条件直接展示，低频条件进入“展开筛选”。
- 表格工具栏保留刷新、密度、列设置和证据导出；导出继续执行权限控制。
- 点击记录打开右侧详情抽屉，宽度建议为 760 至 840px。
- 详情使用 Descriptions、Tabs、Timeline、代码块和关联事件列表组合表达，避免纯文本堆叠。
- 应用请求日志必须展示敏感字段脱敏；Git 同步日志必须展示阶段时间线、失败节点和重试结果。
- 应用请求日志展示请求客户、授权名称、发起请求的客户端应用版本、License ID、到期时间和请求时状态；详情标注“请求时授权快照”。
- Request ID 和 Correlation ID 支持复制与跨类型关联检索，关联结果在抽屉内打开，不丢失原筛选上下文。

## 7. 反馈与边界状态

- 首次加载使用 Skeleton，局部刷新使用组件级 Spin，不使用全屏阻塞加载。
- 空数据使用 Empty，并根据场景提供“清除筛选”“创建记录”或“检查权限”等下一步。
- 接口失败使用 Alert 或 Result 说明错误类型、请求标识和可执行恢复动作。
- 表单校验信息紧邻字段展示，提交失败后自动定位第一个错误字段。
- 保存、复制、导出和重试使用 Message 提供即时反馈；长任务使用 Notification 或页面内状态持续反馈。
- 删除、撤销、拒绝、重新同步和覆盖配置等动作必须展示确认对话框。

## 8. 原型交互保留范围

本次必须保留并验证以下交互：

1. 左侧导航切换全部现有业务页面。
2. 概览指标进入对应筛选列表。
3. 产品、制品、Release、SCM 连接和分发端点列表筛选、分页及详情查看。
4. Release 创建、提交、审批、发布和失败状态反馈的核心流程。
5. 日志中心四类日志切换、查询、详情、脱敏、关联检索和证据导出。
6. Git 同步详情中的阶段时间线和失败重试。
7. 抽屉、弹窗、下拉菜单、复制反馈、空状态及异常状态。

## 9. 非目标

- 不新增租户、计费、License 生命周期、Telemetry、灰度策略等后续阶段业务能力；License 只读请求快照属于已确认 P0 日志字段。
- 不改变现有 P0 发布状态机、权限语义和日志分类。
- 不生成后端、数据库、API 或生产前端实现代码。
- 不把原型升级为 Ant Design Pro 工程模板；本次只在 Open Design 中完成可交互视觉原型。
- 不为展示效果记录或暴露敏感凭据、完整请求体和未脱敏审计数据。

## 10. 验收标准

- 整体框架可明确识别为 Ant Design Pro v6.6.0 企业后台，白色侧栏仍保留 Xminds 品牌识别。
- 所有页面采用一致的 PageContainer、工具栏、表格、抽屉和反馈模式。
- 主色、字体、圆角、间距、状态色和阴影符合本规格定义，不出现混杂组件风格。
- 列表信息密度适中，在 1440px 和 1280px 宽度下关键字段与主操作可用。
- Release 核心流程、日志中心四类日志及 Git 重试时间线均可交互。
- 用户中心、角色与权限、身份源配置可交互；应用请求日志可辨识客户授权快照字段。
- 状态信息不只依赖颜色，危险操作具备明确确认机制。
- 敏感字段保持脱敏，日志和导出相关权限语义不被弱化。
- 原型优化不破坏任何既有业务模块和已确认交互。

## 11. 风险与控制

| 风险 | 影响 | 控制措施 |
|---|---|---|
| 过度套用 Pro 模板 | Xminds 品牌辨识度下降 | 在白色侧栏保留 Logo、主色、现有术语和发布平台专属信息结构 |
| 视觉升级导致信息密度下降 | 运维与审计效率降低 | 使用紧凑表格、展开筛选和详情抽屉分层承载信息 |
| 状态颜色调整造成语义漂移 | 用户误判发布或同步状态 | 建立全局状态映射，同时使用文字、图标和颜色 |
| 改造过程中破坏现有交互 | 原型验收失败 | 对既有核心流程逐项回归，不新增无关功能 |
| 原型与未来技术实现脱节 | 后续重复设计 | 组件结构明确映射到 ProComponents v3，但不提前绑定业务代码 |
