# Xminds Release Platform P0 日志中心原型设计

| 项目 | 内容 |
|---|---|
| 文档版本 | v1.1 |
| 编制日期 | 2026-08-14 |

| 目标载体 | Open Design 网页管理控制台原型 |
| 实施边界 | 仅调整交互原型，不进入业务代码实现 |

## 1. 背景与目标

现有控制台“审计”页面已经具备操作审计查询、详情查看、游标分页和证据导出能力，但不能统一呈现登录、用户应用请求和平台 Git 同步过程。此次设计将现有“审计”升级为“日志中心”，在保留不可篡改审计能力的基础上，形成统一查询和关联排障入口。

## 2. 信息架构

左侧导航将“审计”更名为“日志中心”。页面内部使用四个一级页签：

1. **操作日志**：继承现有审计事件，展示操作者、角色、产品、动作、目标、结果和状态摘要。
2. **登录日志**：展示登录主体、认证方式、来源 IP、客户端、结果、失败原因和会话标识。
3. **应用请求日志**：展示用户应用访问平台 API 的时间、产品、客户、授权名称、发起请求的客户端应用版本、License ID、到期时间、请求时状态、方法、路由模板、HTTP 状态、耗时、请求 ID 和来源 IP。
4. **Git 同步日志**：展示 SCM Provider、仓库、同步方向、Commit/Tag、触发来源、阶段状态、重试次数和请求 ID。

四个页签共享产品范围和环境上下文，但各自保留符合日志类型的筛选条件与表格字段。

## 3. 核心交互

- 支持按时间范围、产品、主体、结果、请求 ID、Correlation ID 和关键词筛选。
- 点击任意记录打开右侧详情抽屉，不离开当前查询上下文。
- 详情抽屉提供“关联事件”区域，可通过 Request ID 或 Correlation ID 串联操作、请求与 Git 同步记录。
- Git 同步详情使用阶段时间线展示拉取、校验、目录生成、状态回写和重试结果。
- 应用请求详情展示脱敏后的请求头、路径参数、响应状态、耗时和错误码，不展示完整请求体或凭据。
- 应用请求筛选支持客户、授权名称、客户端应用版本、License ID、License 状态、HTTP 状态、结果和时间范围组合查询。
- 应用请求详情明确标注“请求时授权快照”，完整展示 License ID、到期时间、校验时间、校验方、允许或拒绝判定及稳定原因码。
- 修改上游客户名称或 License 状态后，历史快照保持不变；原型以不同时间记录演示该语义。
- 保留空结果、失败状态、游标分页、异步证据导出及导出完成反馈。
- 全局搜索输入请求 ID 后，进入日志中心并跨类型定位关联记录。

## 4. 权限与安全

- 审计员可查询授权产品范围内的全部日志并导出证据。
- 管理员可查询全部日志，但证据导出继续受审计权限控制。
- 发布者和审批者仅能查询自身及授权产品范围内的相关记录。
- Token、Cookie、Authorization、密码、密钥和敏感请求体默认不采集或不可逆脱敏。
- License ID 是可审计标识符，不是 License Key；任何列表、详情和导出均不得展示 License Key、签名原文或授权私钥。
- 客户、授权和 License 字段只表示经可信上游校验的结果，不接受客户端自行声明的 Header、Query 或请求体字段作为授权事实。
- 来源 IP、用户代理和会话标识按安全策略展示，导出时继续执行字段级权限控制。
- 日志中心不提供修改、删除和回填入口；原始审计证据保持不可篡改。

## 5. 视觉与可用性

- 延续已确认的 Ant Design Pro v6.6.0 浅色控制台、白色侧栏、低圆角、密集数据表格和白色右侧详情抽屉视觉体系。
- 页签、筛选器、状态颜色、等宽标识符和分页样式复用现有组件规范。
- 表格优先展示定位问题所需的最小字段，长请求路径、摘要和标识符使用截断与等宽字体。
- 失败记录使用克制的红色状态，高耗时使用警告色，不以大面积色块干扰审计阅读。
- 1280px 视口下表格使用容器内横向滚动并固定时间、客户列，页面本身不得出现横向溢出；1440px 视口优先完整展示关键授权字段。

## 6. 原型验收标准

- 左侧导航存在“日志中心”，不再出现独立且重复的“审计”入口。
- 四类日志页签均可切换，且切换后表格字段、筛选项和示例数据同步变化。
- 每类日志至少有一条可点击记录，并能打开对应详情抽屉。
- 应用请求详情体现敏感字段脱敏；Git 同步详情体现阶段时间线和失败重试。
- 应用请求列表和详情可辨识请求客户、授权名称、客户端应用版本、完整 License ID、到期时间及 `有效`、`即将到期`、`已到期并拒绝` 状态。
- 客户、授权名称、客户端应用版本、License ID、状态和时间筛选均可生效，重置后恢复默认列表。
- 详情明确表示数据是请求时快照，不把历史状态表述为当前实时状态。
- 操作日志保留现有不可篡改、游标分页和证据导出能力。
- 全局请求 ID 搜索能够进入日志中心并呈现关联查询反馈。
- 不破坏产品、制品、Release、SCM 连接和分发端点等既有原型流程。

## 7. 风险与后续边界

- P0 原型只表达统一查询与审计交互，不承诺实时日志流或通用全文检索引擎。
- 请求日志必须严格区分“可观测元数据”和“业务敏感载荷”，后续实现不得直接记录完整请求体。
- P0 实施按月分区，默认在线保留 90 天、不可变归档 365 天；跨地域日志湖继续后置。
- License 创建、签发、续期、计量和吊销不属于日志中心；这里只读记录可信上游的请求时授权结果。
