# Xminds Release Platform 日志中心原型执行计划

> **For agentic workers:** 在 Open Design 当前项目内直接执行本计划；只修改原型文件，不实施后端、数据库、采集链路或业务 API。

**目标：** 将现有“审计”页面升级为覆盖操作、登录、应用请求和 Git 同步日志的统一可交互日志中心。

**架构：** 保留单文件交互原型结构，在既有页面状态、导航、表格、页签和抽屉组件上扩展四类日志数据与呈现逻辑。使用 Request ID 和 Correlation ID 表达跨日志关联，权限与脱敏只作为原型规则展示。

**技术栈：** Open Design、单文件 HTML、CSS、原生 JavaScript。

## 全局约束

- 仅修改 Open Design 项目 `xminds-release-platform-p0-console-local-codex-final` 的 `xminds-release-console.html`。
- 不修改 Xminds Release Platform 业务实现代码。
- 保持现有视觉语言、角色切换、产品范围和其他页面流程可用。
- 不展示 Token、Cookie、Authorization、密码、密钥或完整敏感请求体。
- 使用已确认的白色侧栏和白色详情抽屉；应用请求授权字段表示请求时可信快照，不表示当前实时 License 状态。

### 任务 1：升级导航与日志中心状态

**文件：**

- 修改：Open Design 项目中的 `xminds-release-console.html`

- [ ] 将侧栏“审计”文案替换为“日志中心”，保留原导航标识以兼容现有页面状态。
- [ ] 为页面状态增加 `logTab`、查询关键词和关联查询反馈，默认页签为“操作日志”。
- [ ] 增加操作、登录、应用请求、Git 同步四类结构化示例数据，字段包含时间、主体、结果、产品范围、Request ID 和 Correlation ID。
- [ ] 验证刷新后仍可从侧栏进入日志中心，其他导航项保持正常。

### 任务 2：实现四类日志列表与筛选交互

**文件：**

- 修改：Open Design 项目中的 `xminds-release-console.html`

- [ ] 在日志中心页头下增加四个一级页签，并为当前页签提供明确激活态。
- [ ] 操作日志复用现有审计表格、空结果、游标分页和证据导出能力。
- [ ] 登录日志展示认证方式、来源 IP、客户端、登录结果和失败原因。
- [ ] 应用请求日志展示客户、授权名称、发起请求的客户端应用版本、License ID、到期时间、请求时状态、HTTP 方法、路由模板、状态码、耗时、来源 IP 和请求标识。
- [ ] 应用请求筛选支持客户、授权名称、客户端应用版本、License ID、状态和时间组合查询，并支持重置。
- [ ] Git 同步日志展示 Provider、仓库、Commit/Tag、同步方向、阶段状态和重试次数。
- [ ] 切换页签时同步更新筛选器、表头、记录数量和空结果说明。

### 任务 3：实现日志详情与关联追踪

**文件：**

- [ ] 为四类日志记录提供可点击行，并打开沿用现有样式的右侧详情抽屉。
- [ ] 操作详情保留前后状态摘要、来源 IP、请求 ID 和不可修改提示。
- [ ] 登录详情展示认证上下文、会话标识和失败原因，不暴露认证凭据。
- [ ] 请求详情展示脱敏请求头、路径参数、响应状态、耗时、错误码和完整 License ID，并明确标注“请求时授权快照”及敏感字段已隐藏。

- [ ] 在详情抽屉中增加关联事件区，以 Request ID 或 Correlation ID 串联其他日志。
