# 生产泄露口令摘要语料治理规范

## 1. 背景与目标

Xminds Release Platform 在本地账户设置口令前，将候选口令的 SHA-1 和 SHA-256 摘要与受控泄露口令语料进行确定性成员查询。该摘要只用于拒绝已泄露口令，不是平台凭据的存储或认证表示；平台凭据继续使用随机盐 Argon2id。

本规范用于管理生产、预发和测试环境的外部摘要语料，目标如下：

- 语料来源、许可、生成过程和发布责任可追溯；
- 文件只包含摘要，不包含明文口令、账户标识或其他个人数据；
- 引入前完成格式、容量、完整性和安全校验；
- 发布、轮换和回滚过程可重复、可审计且失败关闭；
- 多副本环境使用同一已批准语料版本，避免策略漂移。

## 2. 适用范围与职责

| 角色 | 主要职责 | 禁止事项 |
|---|---|---|
| 安全治理人员 | 批准来源、用途、保留期和风险例外 | 未经证据直接批准未知来源语料 |
| 法务或采购人员 | 核对许可证、再分发和商业使用约束 | 将来源可访问等同于允许生产使用 |
| 平台运维人员 | 构建、校验、部署、轮换和回滚 | 将明文口令、下载凭据或临时文件提交仓库 |
| 发布审批人员 | 复核清单、摘要、版本和验证结果 | 单人完成构建、审批和生产发布 |
| 审计人员 | 核对来源、审批、部署和回滚证据 | 修改构建产物或审批记录 |

## 3. 数据与安全边界

### 3.1 允许的数据格式

每个有效行必须满足以下一项：

- 40 个十六进制字符，对应 20 字节 SHA-1 摘要；
- 64 个十六进制字符，对应 32 字节 SHA-256 摘要。

程序会忽略空行及去除首尾空白后以 `#` 开头的注释行，并将摘要统一为大写后加载。其他长度、非十六进制内容、空语料或超过 128 MiB 的文件均被拒绝。单行不得超过 4096 字节。

### 3.2 禁止的数据

语料及其构建产物不得包含：

- 明文口令、可逆加密口令或口令提示；
- 用户名、邮箱、电话号码、客户标识或泄露来源中的账户关系；
- 上游下载凭据、Cookie、API Token、私钥或解密材料；
- 未经许可允许保存、加工或再分发的数据字段。

摘要语料仍按安全敏感运营数据管理，但不得将其误认为平台密码数据库。SHA-1/SHA-256 的确定性计算只服务于公开摘要集合的成员查询；真正的本地凭据始终由随机盐 Argon2id 保护。

## 4. 来源准入

任何新来源必须形成来源登记记录，至少包含：

1. 来源名称、发布主体、下载地址和获取日期；
2. 原始制品文件名、字节数和 SHA-256 制品摘要；
3. 数据字段说明，确认输入不包含明文口令或账户关系；
4. 许可证、服务条款、商业使用和再分发约束的复核结论；
5. 更新频率、版本标识、撤回机制和安全联系人；
6. 安全治理、法务或采购、平台运维的审批记录。

来源无法证明合法性、完整性或字段边界时不得进入生产。不得通过搜索引擎、论坛附件、个人网盘或未认证镜像直接引入语料。

## 5. 构建与验证

### 5.1 隔离构建

构建必须在受控临时目录中执行，目录权限不高于 `0700`，并遵循以下要求：

- 构建脚本和依赖版本固定并纳入代码审查；
- 输入制品先核对来源登记中的 SHA-256 摘要；
- 只提取已批准的摘要字段，去重后按字典序稳定排序；
- 输出仅包含规范化大写摘要和必要的非敏感注释；
- 不将输入、临时文件、日志或输出提交 Git；
- 构建结束后删除临时目录，并保留不含敏感数据的构建清单。

### 5.2 发布清单

每个语料版本必须生成独立发布清单，至少记录：

- 内部版本号和生成时间；
- 上游来源版本及输入制品摘要；
- 构建脚本提交号和工具链版本；
- SHA-1 条目数、SHA-256 条目数、重复条目数和拒绝条目数；
- 输出文件字节数及 SHA-256 摘要；
- 许可证复核编号、审批人和审批时间；
- 目标环境、计划生效时间和上一可回滚版本。

清单可以进入审计系统，但不得包含明文口令、下载凭据或原始泄露数据。

### 5.3 验证门禁

发布前必须确认：

- 文件大于 0 字节且不超过 128 MiB；
- 所有有效行均可解码为 20 或 32 字节摘要；
- 文件是普通文件，不是符号链接、目录、设备或命名管道；
- 部署副本无任何写权限位，必须由 `root` 或独立部署账户拥有；服务账户仅通过专用只读组读取，例如 `root:<service-group>`、`0440`；
- 语料父目录必须由 `root` 或独立部署账户拥有，服务账户不得写入、重命名或替换其中的文件；
- 输出 SHA-256 摘要与发布清单一致；
- 使用目标版本程序执行启动校验和已泄露/未泄露口令控制测试；
- macOS 构建节点通过仓库元数据清洁检查，输出不含 `.DS_Store`、`._*` 或资源叉。

其中“普通文件、非可写、非空、容量上限、格式和打开前后文件身份一致”由当前程序强制执行；文件及父目录所有权、来源许可、审批清单中的 SHA-256 完整性校验和双人审批属于部署治理要求，不能仅依赖程序启动校验。

## 6. 部署与轮换

1. 使用内容寻址文件名，例如 `breach-corpus-<sha256>.txt`，禁止使用可变符号链接；程序会拒绝符号链接。
2. 由 `root` 或独立部署账户将已验证文件复制到受控目录，核对摘要后设为专用只读组可读且无写权限；父目录不得向服务账户授予写权限。
3. 通过部署配置将 `XMINDS_RELEASE_IAM_BREACH_CORPUS` 指向该绝对路径。
4. 先在一个非生产副本验证启动、已泄露口令拒绝和安全口令放行，再逐步滚动其他副本。
5. 每个副本记录正在使用的语料内部版本和制品摘要；不得记录候选口令或命中摘要。
6. 所有副本完成后，复核版本一致性并关闭变更窗口。

语料在进程启动时加载到内存。替换磁盘文件不会更新已运行进程，因此每次轮换都必须按部署顺序重启并验证所有副本。不得在进程启动校验期间原地改写活动文件。

建议至少每月检查一次上游更新；发现大规模凭据泄露、来源撤回或语料完整性事件时立即启动计划外更新。更新频率可根据组织风险评估提高，但不得跳过来源、许可和验证门禁。

## 7. 回滚与故障处理

- 至少保留当前版本和上一已批准版本的只读制品及发布清单；
- 新版本导致启动失败、异常拒绝率或完整性校验失败时，停止扩大发布并恢复上一内容寻址路径；
- 回滚同样执行滚动重启、控制测试和版本一致性复核；
- 禁止通过启用 development 内置语料绕过生产故障；
- 无可验证语料时保持失败关闭，不得以空文件或跳过泄露检查恢复服务；
- 若来源被撤回或许可证失效，冻结继续分发并由安全与法务共同决定替代或销毁方案。

## 8. 监控与审计

应监控并审计以下事件：

- 语料审批、构建、发布、回滚和退役；
- API 启动时的语料加载成功或失败，但不得记录摘要内容；
- 各副本使用的内部版本、文件摘要和部署时间；
- 本地账户口令因命中语料被拒绝的计数趋势，不记录候选口令或命中摘要；
- 来源更新延迟、制品摘要不一致、容量越界和格式拒绝；
- 异常拒绝率、多个副本版本不一致和未经批准的配置路径变化。

审计记录的保留期应符合组织安全审计与隐私制度。任何包含候选口令、明文泄露数据或下载凭据的日志均视为安全事件。

## 9. 风险分析

| 风险 | 影响 | 控制措施 | 剩余风险 |
|---|---|---|---|
| 来源被篡改 | 错误放行或大量误拒绝 | 来源登记、输入/输出摘要、稳定构建、双人审批 | 上游自身数据质量不可完全验证 |
| 许可证不允许使用 | 合规和法律风险 | 法务/采购准入、许可证复核编号 | 条款变化需要持续跟踪 |
| 语料过期 | 新泄露口令未被阻断 | 月度检查、事件驱动更新、更新延迟告警 | 上游发布仍存在时间差 |
| 语料包含明文或账户关系 | 隐私与泄露风险 | 字段白名单、隔离构建、禁止保存原始字段 | 构建工具缺陷需通过评审与抽样发现 |
| 多副本版本漂移 | 不一致的账户策略 | 内容寻址路径、滚动验证、版本盘点 | 发布中短暂存在双版本窗口 |
| 快速摘要被误作凭据存储 | 弱口令存储风险 | 明确成员查询边界，凭据固定使用 Argon2id | 后续重构需保持边界测试与代码审查 |

## 10. 验收清单

- [ ] 来源、许可证、字段和获取日期均已登记；
- [ ] 输入与输出制品摘要已由不同人员复核；
- [ ] 输出只包含 40/64 字符十六进制摘要和非敏感注释；
- [ ] 输出为非空、普通、非链接、非可写且不超过 128 MiB 的文件；
- [ ] 文件及父目录由 `root` 或独立部署账户拥有，实际服务 UID 无法修改、`chmod`、重命名或替换语料；
- [ ] 已泄露和安全口令控制测试通过，凭据仍使用 Argon2id；
- [ ] 目标环境所有副本均记录同一版本和摘要；
- [ ] 上一版本可用且已完成回滚演练；
- [ ] 日志与清单不包含口令、命中摘要或上游凭据；
- [ ] macOS 元数据清洁检查通过；
- [ ] 审批、发布和验证证据已进入审计系统。
